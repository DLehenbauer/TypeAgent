R1 -- Dead code / reduced complexity.

Hunt for code that can be removed or simplified without changing behavior:

- Unused exported or unexported functions, types, methods, fields, constants, or
  variables (no call sites anywhere in the repo -- verify with a grep before
  flagging).
- Dead branches, unreachable code, redundant error checks, and parameters that
  are always passed the same value or never used.
- Concepts on the public/authoring surface that earn no behavioral variance --
  two names that obey one rule and could be one parameterized concept.
- Needless indirection: a one-call-site helper, a wrapper that only forwards.

## Coverage signal

The baseline coverage entries for THIS file (extracted from `go test
-coverprofile`) are at `{{coverProfile}}`. Each line is a block; a trailing
count of `0` means the block never executed under the test suite and is a strong
lead for unreachable or dead code. If that file is absent or empty, the file
simply had no coverage data -- treat it as no signal, not as dead code. Confirm
there are no call sites before flagging, since a block may just be under-tested.

Countable proxy: exported-identifier count, cyclomatic complexity over
threshold, and dead-code count should go DOWN. Deleting an unbuilt/unused concept
counts the same as deleting an implemented one.

Do NOT flag things that are merely "verbose" or "could be shorter" with no
removal of a concept or branch -- that is a symmetric rationale.
