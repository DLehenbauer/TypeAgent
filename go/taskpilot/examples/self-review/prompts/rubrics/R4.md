R4 -- Correctness-by-construction.

Make illegal states unrepresentable and push invariants into the type system:

- `any` / `interface{}` on EXPORTED signatures where a concrete type or a small
  interface would do. Each one removed is a counted movement.
- "Caller MUST do X" / "callers are responsible for Y" comment contracts that
  could be enforced structurally (constructor that validates, unexported field
  with an accessor, a type that can only be built valid).
- Sibling fields where one is only valid when another holds a certain value
  (conditional-on-sibling) -- prefer a sum/variant shape that cannot be invalid.
- Functions returning `(T, error)` whose error is impossible, or that panic on
  programmer error where a typed result would be safer.
- Validation that happens deep inside instead of at the boundary.

Countable proxy: exported `any` count DOWN; comment-enforced contracts converted
to language-enforced ones; impossible error returns removed.

When a state genuinely can't be made unrepresentable, enforce the invariant at
the boundary and fail loudly (error, or panic on a true programmer-error). This
code base is fail-fast: never swallow an error, and never coerce an illegal
state into a legal one (no clamping, silent defaulting, or best-effort fixups). An
unchecked invariant is itself a defect to flag.
