R6 -- Documentation sync / comment-code consistency. WHOLE-REPO axis.

Three sub-checks:

1. Missing contracts/intentions. Every exported function/type and every
   non-obvious block should carry a brief doc comment stating its contract (what,
   params/returns, errors, invariants) or the WHY of the step. Flag gaps.

2. Drift. Compare each existing comment against the CURRENT code it describes and
   flag where it no longer matches: stale parameter/return descriptions, claims
   about behavior the code no longer has, references to renamed/removed symbols,
   historical notes ("used to", "previously") that document the past not the
   present.

3. Directive fulfillment. Find in-comment instructions such as "if you change X
   also change Y", "keep in sync with Z", "must match", "mirror", "in lockstep".
   GREP for the referenced target and VERIFY it is actually consistent. If the
   directive was not followed (Y drifted from X), the fixTarget is the side that
   must change to restore consistency -- which may be a DIFFERENT file than the
   comment.

Evidence is REQUIRED: cite the comment location and, for drift/directives, the
diverging code location (`file:line`).

Countable proxy: drift instances DOWN; unfulfilled directives -> 0; missing
contracts DOWN.

Do NOT flag correct comments as "too verbose" or rewrite for style -- only
missing, drifted, or unfulfilled documentation qualifies.
