R3 -- Maintainability / coupling.

Flag structure that forces wide, correlated edits or violates layering:

- Sets of files/functions that must change together for the next plausible
  extension. Name the extension concretely and count the coupled edit sites; the
  fix reduces that count.
- Layer-direction violations: a lower-level package importing or depending on a
  higher-level one; a core type reaching into an outer concern.
- A single function or type that mixes unrelated responsibilities such that an
  unrelated change forces touching it.
- Data passed through many hops only to be used far away, when a clearer boundary
  would localize it.

Countable proxy: coupled-edit count for the named extension -> DOWN;
layer-direction violations -> 0.

Do NOT propose speculative abstractions for hypothetical future needs. Collapsing
two real call sites into one is fine -- just do not be silly about it (no
extracting a one-off with a single real use). "More flexible" / "more extensible"
with no named, counted coupling reduction is a symmetric rationale and is
rejected.
